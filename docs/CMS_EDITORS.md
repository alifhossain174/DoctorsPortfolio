## Controls, validation and saving

All managed text uses the existing `x-admin.localized-tabs` English / বাংলা editor, Eloquent JSON arrays and `LocalizedContent`: selected non-empty locale → non-empty English → safe empty state. Missing Bangla is indicated. Both translations are present in one form; tab switches retain unsaved input. Internal line breaks and Bengali UTF-8 are retained; Blade escapes content, and the small public interaction stylesheet preserves plain-text line breaks without changing the reference stylesheet or markup.

Controls are purpose-built: short text, bounded textareas, allowlisted fact formats, typed internal/external destination selection, enums, 0–24 homepage counts, visibility checkboxes and the existing media picker. Address/hours/Friday text use multiline controls with their original short-text server limits. Image ratios/DOM/classes/layout remain fixed. Requests authorize the admin Gate and whitelist each screen's owner fields, content-field IDs and section IDs, nested language keys and control structure. Unsafe URLs, credential-bearing URLs, protocol-relative URLs, nonexistent/admin route keys, unknown fields, cross-screen IDs, extra languages, invalid enums/counts/media IDs and attempts to hide/reorder required sections are rejected. Appointment CTA destinations remain the named `contact` route; Facebook remains a separate social link. Copyright translations require `{year}`; `WebsiteContent` supplies the current year, alongside approved fact placeholders. Executable template syntax is never evaluated, and text is never rendered as raw HTML.

Ordinary CSRF-protected POST/PUT/DELETE requests use Laravel redirects/validation/flash feedback. `CmsEditorSaver` reuses `AdminContentWriter`, including complete-record registry validation, row locking, safe trimming and translation merging. A settings/page multi-record save uses one outer transaction: failure in any field rolls back earlier writes. Database failure gets a friendly retry message and retained input. Only a request-scoped content snapshot exists; writes discard that snapshot synchronously. The next public request reads the database, with no long-lived cache or initialization/source fallback.
