Decision date: 2026-10-10. Steps 1–13 include the Laravel scaffold, actual relational schema, verified initialization, public Blade pages, private authentication/dashboard/profile, synchronous media management/shared picker and structured settings/page/navigation and independent care/service/consultation and category/article/gallery editors, kind-scoped private inquiry inboxes and the completed real-data dashboard. Meaningful foreign keys restrict required category/gallery-media/page relationships; nullable references become null when removed. Application validation uses portable strings for status values rather than engine-specific enums. Required English values are checked on saves; optional Bangla falls back through LocalizedContent. Blade escapes paragraphs/editor text; no stored executable templates.

`config/cms_models.php`, `config/content_fields.php` and `config/page_sections.php` and `config/private_content_fields.php` form the content registry. `ContentRegistry` exposes owner/group/control/requiredness and expanded server validation rules; each named control overrides generic ContentField.value. CmsModel whitelists fillable fields and validates saves, including direct unknown attribute changes. Future admin controllers must use registry-approved editor controls and validated request fields, preserving the other language. Technical keys/positions stay code-owned.

`LocalizedContent::resolve` handles locale text and structured bodies: selected locale with actual content → non-empty English → supplied empty safe state. Null, whitespace, empty arrays and recursively empty structures do not suppress fallback. `WebsiteContent` reads database fields/settings per request and performs plain-text allowlisted formatting; it contains no demo copy fallback. There is no source/snapshot/seed file read in a controller/view/public script.

Public routes implemented: GET /, /about, /services, /diagnostics, /blog, /gallery, /contact, /blog/{post:slug}; POST /inquiries; Laravel /up. SetPublicLocale is registered as public.locale in bootstrap/app.php and applied to the public group in routes/web.php (no Kernel.php). Validated ?locale=en|bn overrides session public_locale, then database default_locale, then en. The preference is kept in Laravel's file session, identified by its session cookie. Unsupported scalar/array query values are ignored. All eight .html entry points have named compatibility routes; article.html?id=slug redirects only published, non-future posts, otherwise 404. Private auth/profile, media, settings/page/navigation and care/service/consultation routes are implemented. Article/category/gallery editors and both private inboxes are now implemented; all admin actions retain the same guards.

The populated Blade foundation preserves original CSS/DOM classes, shares hero/CTA/article/gallery/filter parts, and uses only public/assets/style.css plus interaction-only public.js. Admin Vite assets are isolated. GET category filters and language/mode switches work without submission side effects. The contact mode selector has its own GET form; the inquiry POST uses CSRF, throttle, localized validation, a synchronous save and internal PRG success. Consultation is appointment-only; separate Facebook/Maps anchors retain original targets. Phone is now required for follow-up; optional email is model-only initially. No clipboard or external window is opened on submission.

Explicit initialization: `php artisan migrate`, then `php artisan db:seed`. DatabaseSeeder calls InitialWebsiteContentSeeder, which delegates to InitialWebsiteImporter. A transaction and marker row lock serialize initialization; missing records are created by stable identity, never upserted with defaults. Completion commits only with all records. Repeated normal seeding skips completed content completely; other explicit seeders can still run. No boot/web/login/deployment auto-import. `database/seeders/data/initial-website.json` is verified UTF-8 initialization input, including original provenance and destination mapping; production seeding needs no frontend/ or Node.

Explicit missing-only repair: `php artisan website:repair-initial-content`. It checks the original snapshot checksum and recreates missing demo rows only, leaving existing edits/drafts/hidden rows/passwords intact. An owner must deliberately invoke it because deleted originals can return in their initial visible/published state. No migrate:fresh, owner overwrite or destructive reset. Test DML runs inside rollback transactions only in doctor_portfolio_test, with separately applied non-destructive migrations.

Actual initialization/import counts, bilingual verification, form changes and unresolved remote images are in SEED_CONTENT_REPORT. Step 4 verifies public routes, structural fidelity, locale/filter/redirect boundaries and interaction behavior; actual desktop/mobile browser screenshots remain unavailable and have a manual checklist in PUBLIC_VERIFICATION. Admin auth/editors, private inquiry management and validated uploads are implemented in their later sections below; remaining public SEO/hosting is subsequent work.

## Step 4 public rendering and interaction boundary

- PublicPageController loads only collections needed by the selected page, eager-loads category/media relations and resolves publication/filter scopes before rendering. WebsiteContent is scoped per request and shares database settings/typed fields with locale middleware and controllers. Blade loops make no database queries. Hidden navigation labels remain available for the shared contact headings; only visible items become navigation links.
- public/layouts/app.blade.php owns the document; public/page.blade.php selects the fixed page template. Topbar/navigation/footer/CTA/hero/notice/care-card/article-card/gallery-item/image/paragraphs/lightbox are reusable partials. The original public/assets/style.css stays byte-identical. A tiny interactions.css restores original button font/line-height on native GET anchors and adds keyboard focus outlines; it contains no reset. Public layout never loads admin Tailwind/Vite entries or the source app.js.
- PublicUrl creates named internal links with locale. The same-route language switch preserves applicable database category slugs, a positive page value (1–999999), and contact mode; it discards unrelated/invalid queries. Category changes reset pagination. There is no pagination yet; future pagination must reuse the already filtered query and append the same validated query set. Filters work across the full database collection without JavaScript.
- New public.js enhances the mobile menu, native filter feedback, lightbox and GET contact-mode selector only. Lightbox URL/caption/alt come from escaped database attributes, captions use textContent, the single close control traps Tab/Shift+Tab, Escape/backdrop/button close restores focus and scroll, background siblings become inert temporarily, and previous inert/overflow states are restored. No translation/content catalog, localStorage, innerHTML, client routing or client-only filtering exists.
- Localization always uses LocalizedContent for strings and structured bodies. Empty/missing bn (including empty/null bodies) falls back to meaningful en; both absent produces the defined empty state. html lang, titles, metadata, labels, badges, captions, alt, links and errors resolve on the server. A copied ?locale=bn URL reproduces Bangla independently of prior session state.
- Both contact forms carry hidden locale; the inquiry handler validates it and uses a valid URL locale first, otherwise supported hidden locale for form feedback. Success/errors redirect only to the named internal contact route with validated mode/locale; Referer/visitor redirect targets are never used. The existing Step 3 synchronous save handler remains; no placeholder success was added. Complete inquiry workflow/hardening is reserved for the owner's Step 11, and private staff screens for Step 13.
- HTTP(S) targets are checked again when rendered. Local media URLs require the public-media disk and validated random raster path; unsafe or absent media yields no image element, while a real remote URL retains its source dimensions/classes even if the remote host fails. No remote fetch, fabricated replacement, raw HTML/SVG or stored executable template is used.
- Article body stays {en:[plain paragraph strings],bn:[plain paragraph strings]}; public.parts.paragraphs emits escaped p elements. Reuse admin.partials.paragraph-repeater/paragraph-row and admin.js add/remove/up/down controls in later article CRUD. Native names are body[en][] and body[bn][] in DOM order. The future registry-backed request trims/removes blank paragraphs, requires non-empty English and stores missing Bangla as null; it must validate each plain string and never introduce rich text/HTML/Markdown.

Step 5 adds no dependency. ## Registry, localization and rendering

Code registry (e.g. config/content.php) defines specific fields from CONTENT_MATRIX: headings/descriptions/eyebrows, CTA label/target, alt/media slots, form/UI messages, copyright/title formats and metadata. Types: localized short text (typically <=255), localized long plain text (bounded), localized validated link target, media reference with local-image constraints, and localized format with allowlisted placeholders. Registry-specific rules override generic limits; validate both locale keys and disallow extra keys. Required English fields must be nonblank; optional Bangla may be blank and use the common fallback. Do not let admin rename structural registry keys or paste JSON.

One LocalizedContent service/accessor is used by settings, fields, collections, link targets, alt and metadata: requested supported locale's nonblank value → English nonblank value → empty string. It never reads source/seed files, returns registry keys as display text, or calls a translation API. Missing required database content is a setup error to resolve via explicit initialization; no demo fallback at runtime. Format interpolation uses the same locale-resolved shared values. Registry remains validation/layout code and contains no runtime demo values. Both English / বাংলা editor panels preserve the other language when one is edited.

Locale resolution is now the implemented Step 4 rule above: validated `?locale=en|bn`, session public_locale, database default_locale, en. The earlier Step 3 ?lang parameter is superseded. Middleware sets Laravel's locale using configuration in bootstrap/app.php. Language/filter/mode controls are ordinary purpose-specific GETs; they never create inquiries. Any future search requires its own validated GET query before it is carried through links. Primary pages and complete category filtering work without JavaScript.

## Inquiry workflow and truthful default copy

Keep `.info-box`, `.form`, `appointmentForm`, and existing field layout; add semantic name attributes and normal POST action. Selector options are localized labels, submitted values are fixed appointment/general. Show consultation type only for appointments; vanilla JS toggles visibility/required/disabled, while a GET mode link/form gives a functional no-JS choice. Server enforces mode independently. Request records remain separate from sessions/cache. Save before success; DB failure yields no success. PRG preserves validation errors and old input, prevents refresh resubmission, and never copies text or opens Facebook.
