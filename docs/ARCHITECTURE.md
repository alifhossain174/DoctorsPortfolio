All tables use utf8mb4/utf8mb4_unicode_ci; casts are explicit. Slugs/keys/reference are unique; statuses/publication time/order/inquiry status+created_at are indexed. Meaningful foreign keys restrict required category/gallery-media/page relationships; nullable references become null when removed. Application validation uses portable strings for status values rather than engine-specific enums. Required English values are checked on saves; optional Bangla falls back through LocalizedContent. Blade escapes paragraphs/editor text; no stored executable templates.

`config/cms_models.php`, `config/content_fields.php` and `config/page_sections.php` and `config/private_content_fields.php` form the content registry. `ContentRegistry` exposes owner/group/control/requiredness and expanded server validation rules; each named control overrides generic ContentField.value. CmsModel whitelists fillable fields and validates saves, including direct unknown attribute changes. Future admin controllers must use registry-approved editor controls and validated request fields, preserving the other language. Technical keys/positions stay code-owned.

`LocalizedContent::resolve` handles locale text and structured bodies: selected locale with actual content → non-empty English → supplied empty safe state. Null, whitespace, empty arrays and recursively empty structures do not suppress fallback. `WebsiteContent` reads database fields/settings per request and performs plain-text allowlisted formatting; it contains no demo copy fallback. There is no source/snapshot/seed file read in a controller/view/public script.

Public routes implemented: GET /, /about, /services, /diagnostics, /blog, /gallery, /contact, /blog/{slug}; POST /inquiries; Laravel /up. ResolvePublicLocale is attached explicitly to this public route group in routes/web.php, using Laravel 12 conventions (no Kernel.php). Supported GET lang overrides session, then database default_locale, then safe en. Legacy .html compatibility is pending Step 4. Admin routes/screens remain Step 5 onward.

The populated Blade foundation preserves original CSS/DOM classes, shares hero/CTA/article/gallery/filter parts, and uses only public/assets/style.css plus interaction-only public.js. Admin Vite assets are isolated. GET category filters and language/mode switches work without submission side effects. The contact mode selector has its own GET form; the inquiry POST uses CSRF, throttle, localized validation, a synchronous save and internal PRG success. Consultation is appointment-only; separate Facebook/Maps anchors retain original targets. Phone is now required for follow-up; optional email is model-only initially. No clipboard or external window is opened on submission.

Explicit initialization: `php artisan migrate`, then `php artisan db:seed`. DatabaseSeeder calls InitialWebsiteContentSeeder, which delegates to InitialWebsiteImporter. A transaction and marker row lock serialize initialization; missing records are created by stable identity, never upserted with defaults. Completion commits only with all records. Repeated normal seeding skips completed content completely; other explicit seeders can still run. No boot/web/login/deployment auto-import. `database/seeders/data/initial-website.json` is verified UTF-8 initialization input, including original provenance and destination mapping; production seeding needs no frontend/ or Node.

Explicit missing-only repair: `php artisan website:repair-initial-content`. It checks the original snapshot checksum and recreates missing demo rows only, leaving existing edits/drafts/hidden rows/passwords intact. An owner must deliberately invoke it because deleted originals can return in their initial visible/published state. No migrate:fresh, owner overwrite or destructive reset. Test DML runs inside rollback transactions only in doctor_portfolio_test, with separately applied non-destructive migrations.

Actual initialization/import counts, bilingual verification, form changes and unresolved remote images are in SEED_CONTENT_REPORT. Full desktop/mobile browser QA, legacy redirects, admin auth/editors/inquiry management and validated upload workflows remain subsequent work; the initial public foundation is already readable in both languages.

## Stack, boundaries and dependencies

Use Laravel 12.x with PHP 8.2, Blade, Eloquent, ordinary web controllers/FormRequests, and vanilla JavaScript on public and private screens. Laravel's version-specific deployment docs require PHP >=8.2 and a public document root ([Laravel 12 deployment](https://laravel.com/docs/12.x/deployment)). Use Laravel's native session auth, hashing, CSRF, validation, pagination, filesystem and throttling. No starter kit: do not import framework dependencies through Breeze, Jetstream or another kit. Do not add React/Vue/Angular/Svelte/Next/Alpine/Livewire/Inertia or a SPA. No third-party auth, public registration or patient accounts.

Composer dependency is laravel/framework ^12.0 via a compatible Laravel skeleton, with only its necessary defaults and a modest development test toolchain. Build-time Node is permitted for compiled admin-only Tailwind (and minimal asset compilation tooling if needed). No runtime Node service. Preserve public CSS/DOM; copy approved stylesheet into public assets later without changing frontend/. Use separate public and admin Blade layouts and asset bundles: public loads original design CSS and new interaction-only JS; admin loads compiled Tailwind and plain JS. Never load original app.js or admin Tailwind on public pages. No queue/schedule/Redis/Docker/WebSocket/payment/booking stack. File sessions and file cache; synchronous requests; content reads from MySQL/MariaDB.

## Registry, localization and rendering

Code registry (e.g. config/content.php) defines specific fields from CONTENT_MATRIX: headings/descriptions/eyebrows, CTA label/target, alt/media slots, form/UI messages, copyright/title formats and metadata. Types: localized short text (typically <=255), localized long plain text (bounded), localized validated link target, media reference with local-image constraints, and localized format with allowlisted placeholders. Registry-specific rules override generic limits; validate both locale keys and disallow extra keys. Required English fields must be nonblank; optional Bangla may be blank and use the common fallback. Do not let admin rename structural registry keys or paste JSON.

One LocalizedContent service/accessor is used by settings, fields, collections, link targets, alt and metadata: requested supported locale's nonblank value → English nonblank value → empty string. It never reads source/seed files, returns registry keys as display text, or calls a translation API. Missing required database content is a setup error to resolve via explicit initialization; no demo fallback at runtime. Format interpolation uses the same locale-resolved shared values. Registry remains validation/layout code and contains no runtime demo values. Both English / বাংলা editor panels preserve the other language when one is edited.

Locale resolution: validated `?lang=en|bn` first, existing session locale second, `en` default. Middleware persists supported query locale and sets app locale in `bootstrap/app.php`, following [Laravel 12 middleware configuration](https://laravel.com/docs/12.x/middleware). Language switch is a normal GET to the current allowed route preserving safe filter/search parameters, not an inquiry submission; invalid locale is ignored. Use one request-resolved locale everywhere, including html lang, metadata, nav, messages, validation and old-input forms. No JS/localStorage source of truth is required. Server renders complete pages without JS; JS only enhances menu, filters, lightbox and conditional mode display. Collection filters can use GET category with optional vanilla hiding enhancement; no backend depends on client content arrays. If future search is added it is a GET search, never an inquiry.

## Upload and demo initialization strategy

Images upload synchronously through admin only, validate JPEG/PNG/WebP MIME and extension, byte/dimension limits (proposed 5 MiB, 6000px maximum edge), reject executable files/SVG, generate random filenames and store through Laravel's local disk. Store original provenance and localized alt/caveat; escape captions. No unauthenticated remote-URL fetcher; prevent SSRF. Replace media references explicitly; prevent deleting referenced assets. Public approved images are public; inquiries and admin content are never stored on the public media disk.

Default public media uses storage/app/public + public/storage link per [Laravel 12 filesystem docs](https://laravel.com/docs/12.x/filesystem). If cPanel disallows symlinks, choose a configured public upload disk under public/uploads with non-executable Apache rules, or a controlled image response from local storage; test that concrete host. Do not expose all storage or change global services. No cloud media dependency. Source has no local images: development acquisition is a bounded explicit operation using audited URLs, recording actual failures. Do not claim the signed hero is a verified doctor portrait. If an asset cannot be obtained, report its slot and use a truthful missing-media presentation until approved replacement; no silent fabricated photo.

Later initialization snapshots all 81 pairs, literal strings, four articles with all paragraphs, eight gallery entries, five service blocks, four care cards and shared assets into explicit versioned seed/import data. It does not read frontend files at runtime. Create fresh demo rows as visible/published, so the imported demo immediately renders without an admin content-entry prerequisite. Preserve caveats; add Bangla for English-only UI literals without adding medical claims. Apply intentional inquiry wording changes above. No automatic seeding during web requests or deployment boot.

Repeat initialization uses stable identities and insert-if-missing only, including locale values/visibility/status: do not upsert-overwrite existing rows, backfill an intentional owner's empty translation, republish a draft or unhide an item. A small import ledger (`import_records`, source_key unique plus model/key identity) retains initialized/tombstoned identities if a collection record is later removed, so a rerun cannot resurrect an owner's deleted demo entry. Alternatively retain archived rows with stable identities; implementation must cover deletion before claiming safe repeat imports. Import transaction + counts/missing-field report; no migrate:fresh, truncate, reset or unrelated schema writes. Admin provisioning separate from demo import; never reset passwords.

## Local and cPanel hosting approach

Local root is the current DoctorPortfolio folder, with PHP 8.2 CLI present. Laravel is served using `php artisan serve` from this root; XAMPP provides a dedicated MySQL/MariaDB database only. Confirm Composer and required PHP extensions in the scaffold step; confirm database service/credentials without touching other databases. Do not assume MySQL is reachable or preconfigured from PHP availability. Use `.env` (not committed), `.env.example` placeholders, APP_KEY, correct APP_URL, DB connection, SESSION_DRIVER=file, CACHE_STORE=file. No database or services were contacted this step.

Production: cPanel PHP 8.2 and required extensions, Apache rewrites, MySQL/MariaDB, HTTPS, write access for storage/bootstrap/cache. Put application core outside public_html; point domain document root at Laravel public where supported. If a host requires public_html, copy only public contents there and adjust index.php paths to a private application directory; never expose root, .env, vendor, frontend, database dumps, private storage or docs. Ship Composer production vendor and compiled assets from a trusted build environment if host lacks CLI/Node. No production asset compiler process. Configure secure session cookies, APP_ENV=production/APP_DEBUG=false; create APP_KEY once and preserve it. Back up before migrations; run non-destructive migrate --force and caches deliberately; do not reset data or auto-import over owner content.

Security boundaries: CSRF/authz on admin mutation; public input independently validated; Eloquent bindings; escaped Blade plain text and safe URL schemes; required visibility scope on all public collection queries; password hashes and session fixation protection; upload execution prevention; server errors disclose no secrets or private inquiry data. Configure retention with the owner later and use manual admin housekeeping if required, not scheduled jobs. cPanel capabilities/database access/approved media remain unverified until their dedicated steps.
