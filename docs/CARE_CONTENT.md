Each collection provides GET index/create/edit, POST create, PUT update, DELETE delete, PATCH `/{id}/move` and PATCH `/{id}/visibility`. All 24 new routes inherit session `auth/admin/auth.session`, the guarded admin controller, CSRF and Gate authorization. Only implemented sidebar destinations link. The code-owned `config/care_collections.php` binds these three owners; neither submitted model names nor a query string can select an arbitrary model. There is no public collection write endpoint or raw JSON editor.

Care-card editors save localized `title`, `description`, `icon`, `link_label` and `target`. Icons are selects from `🤰 ✿ ♡ 🔬 ✚ ✳`; no raw SVG/HTML. Targets are restricted to named `services` or `diagnostics` in both translations, with locale-aware public links. Services save localized `title` and plain-text `body`; the unique lowercase service slug is chosen when creating and stays fixed afterwards. Existing stable keys are read-only; custom card/service keys are generated securely. No stored ordinal label or appointment-selectable service flag exists.

Consultation options save one stable lowercase key at creation and localized `label`; existing keys cannot change. Original identities remain `obstetrics`, `gynecology`, `fertility`, `diagnostics`, with both original translations and original order. They represent obstetrics/pregnancy, gynecology, infertility/IUI and diagnostics respectively. Editing a card or service does not alter a consultation label. An option may be renamed, disabled or deleted independently. Inquiry creation already snapshots its stable key and full bilingual label. Existing snapshots are never updated by option changes; the nullable `nullOnDelete` foreign key retains the inquiry on deletion. Public submissions reject inactive/missing choices. No fake inquiries were inserted in development.

All managed text uses the existing English / বাংলা tabs, JSON `{en,bn}` casts and `LocalizedContent`. Both panels submit together; switching tabs retains input. Partial updates merge the omitted language from the locked record. Empty Bangla falls back to English, missing Bangla is indicated, and required English is validated. Text is escaped; newlines remain plain text. Records append to their own list, and the small lists intentionally display all rows so accessible Move up/down controls operate over the entire collection without ambiguous pagination boundaries.

Every collection mutation runs in a database transaction. It locks the existing primary SiteSetting as a serialization anchor without modifying it, then locks its collection in `sort_order,id` order. Create/delete/move normalize zero-based positions, updating only changed positions. A move swaps neighboring rows, including disabled records; boundary moves safely do nothing. Enabled public rows retain relative order, so Services always displays contiguous `01…` numbers. Confirm disabling before either an inline visibility change or a form save; enabling needs no extra confirmation. Deletion uses the shared confirmation dialog/native checkbox and normal DELETE request. Failures roll back and show retry/validation feedback. Request-scoped website snapshots are discarded synchronously.

Diagnostics reuses its eight registered page fields: `diagtitle`, `diagdesc`, `diagtags`, `diagtagsdesc`, `diagnotice`, `image`, `image_alt`, `contact_target` (all prefixed `diagnostics.`). Page.label supplies its eyebrow. Clinic label/address/hours and visiting format remain shared settings/fields; the button label comes from the shared Contact navigation label and its destination remains `contact`. Shared CTA text/target use Website Settings. The original availability caveat is unchanged by other edits and requires non-empty English; only an intentional owner edit replaces it. No tests/prices/slots/reports/catalog were added.

Initial populated public markup/classes/styles/order are unchanged. If an owner disables/deletes every card or service, the same grid displays the existing localized database empty-state copy; notices/CTA remain. With no active options, appointment mode explains the empty state and disables its submit button, while General contact remains available. The server still rejects an inactive/missing appointment choice. These empty branches are intentional additions for CMS-managed visibility, not a redesign of the original populated site.

Ordinary repeated `db:seed` skips the completed import and cannot resurrect deliberately deleted originals or reset visibility/order/edits. Restore missing originals only through the existing explicitly documented repair command. Production still needs no source frontend or Node runtime for initialization/rendering.
